Fixed Bugs

# Severity Title File(s) Changed Status
1 Critical Scatter regression — unpaired xs/ys arrays
xs and ys were filtered independently: a row with a valid x but null y would appear in xs but not ys, producing mismatched array lengths. linearRegression() returns null when lengths differ, silently disabling the regression line whenever any point had a missing coordinate.
Fix: Pre-filter to rows where both x and y are finite before splitting into xs / ys arrays, keeping them paired.
const paired = rows.filter(r => isFinite(Number(r[xCol])) && isFinite(Number(r[yCol])))
DataVisualizationPage.tsx:185 Fixed
2 High Bar-horizontal — axis labels swapped
The value axis (xAxis in ECharts horizontal bar) was labelled with customization.yAxisLabel, and the category axis (yAxis) with customization.xAxisLabel. This meant every user-entered axis label appeared on the wrong axis.
Fix: Swapped the assignments — value axis gets xAxisLabel, category axis gets yAxisLabel.
xAxis.name = customization.xAxisLabel || yCol
yAxis.name = customization.yAxisLabel || xCol
echartsBuilder.ts:200–201 Fixed
3 High Faceted chart — panel titles not rendered
Panel title labels were placed using ECharts graphic elements with left: "33%" / top: "8%". ECharts graphic components use pixel-based coordinates only — percentage strings are silently ignored, so all facet panel titles appeared at position (0, 0) or were invisible.
Fix: Replaced graphic array with ECharts' title array. The title component natively supports percentage strings for left / top, placing each label correctly in its panel.
echartsBuilder.ts:648–669 Fixed
4 Medium Field detector — leading-zero strings classified as numeric
The comment in isNumericValue stated a leading-zero guard existed, but the guard was missing. Number("007") = 7 (finite), so zip codes, padded IDs, and similar strings were classified as numeric instead of categorical. This caused incorrect axis type selection and broken field-mapping suggestions for ID columns.
Fix: Added the missing guard before Number():
if (/^0\d/.test(trimmed)) return false
Consistent with the existing isNumericString guard in the cleaning feature.
fieldDetector.ts:28 Fixed

Known Limitations (not fixed — out of scope for this audit)

# Severity Title Notes
L1 Low Series lookups use rows.find() — returns first match only
In bar-vertical, bar-grouped, bar-stacked, line, area (all with a series column), the per-category value is resolved with rows.find(r => r[xCol] === cat && r[seriesCol] === g). If raw data is not pre-aggregated (multiple rows with the same x + series pair), only the first row's value is used instead of the sum. 		Only manifests when aggregation is not applied. The correct fix is to pre-aggregate data, which requires a UI change outside the scope of a pure bug audit.
L2 Low Group-by dropdown excludes date columns
AggregationPanel shows only categorical and boolean columns in the Group By selector. Date columns are a valid grouping key but are absent from the list. 		UX improvement rather than a data-correctness bug. No data is corrupted — date columns simply cannot be chosen as a group-by key in the current UI.
